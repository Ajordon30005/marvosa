## What This Is

Classical RAG: embed documents → store vectors on disk → query → cosine
similarity scan → retrieve chunks → inject into context. This requires
disk space, RAM for the index, and O(N) compute per query.

Topological RAG (this system): the entire memory of the system exists as
one HCL braid equation. Each memory is one FBit term. The equation IS the
index. Retrieval is computing which terms of the equation resonate with a
query FBit — no disk scan, no vector database, no file I/O.

The analogy to human brain topology is exact: a human can lose large
physical regions of cortex and recover memories because the memory was
never stored in specific neurons — it lived in the topological invariants
of the connectivity pattern. Those invariants survive physical damage. Here
the memory lives in the winding number, writhe, and Jones span of the braid
— invariants that survive any substrate change.

## ABSOLUTE RULES

**Rule 1: NO DISK I/O for memory.** No files. No JSON blobs. No SQLite.
No `.lqts` files. No `os.path`. No `open()`. The memory exists in one
Python integer — the composite braid amplitude — and a braid log list in
RAM that is O(k) where k = number of memories, not O(content size).

**Rule 2: NO FLOATS.** All arithmetic uses the HCL pure integer system:
SCALE = 10^PREC, all values are integers. The four params η, λ, γ, β are
exact integers. No `numpy`. No `math.exp`. All series are integer Taylor.

**Rule 3: NO IMPORTED CONSTANTS.** π, e are derived from the four params
through HCL operations exactly as in the hcl-pure skill.

**Rule 4: THE MEMORY SIGNATURE IS A TOPOLOGICAL INVARIANT.** The signature
of the entire memory system is the Jones span + winding number + writhe of
the composite braid. These three integers completely characterize the system
state. You can reconstruct which memories exist by solving the braid — not
by reading a file.

**Rule 5: RETRIEVAL IS BRAID RESONANCE, NOT COSINE SIMILARITY.** A query
is encoded as a FBit. Memories resonate when COMP(query_fbit, memory_fbit)
produces constructive interference (large amplitude). Destructive
interference = no match. This is exactly Deutsch-Jozsa / Grover in HCL.

**Rule 6: THE CONTENT IS NEVER STORED.** Only the topological signature of
each memory is stored (3 integers: n_w, writhe_int, jones_span). The full
content is either: (a) reconstructed from context if small enough, or (b)
referenced by a short content key that the caller manages. The system stores
WHERE a memory lives in braid space, not WHAT the memory contains.

## Architecture

```
SYSTEM STATE (entire memory lives here — no disk):
  composite_braid: list of BraidTerm
  
  BraidTerm = {
      content_key: str        # short identifier (not the content itself)
      n_w:         int        # winding number   — topological charge
      writhe:      int        # writhe (×SCALE)  — topological spin  
      jones_span:  int        # Jones polynomial span — complexity depth
      w_level:     int        # collapse weight
      phase_frac:  int        # FBit phase [0, SCALE)
      amp:         int        # FBit amplitude in fixed-point
  }

STORE(content_key, content_text):
  1. Encode content_text → FBit via HCL (pure integer, no floats)
  2. Compute topological invariants (n_w, writhe, jones_span)
  3. Append BraidTerm to composite_braid
  4. Update system signature (3 integers)
  → O(1) RAM per memory. Content itself not stored here.

RECALL(query_text, k=5):
  1. Encode query_text → query_fbit
  2. For each BraidTerm: compute COMP(query_fbit, term_fbit) amplitude
     → constructive = resonance = match
     → destructive = no match
  3. Return top-k content_keys by resonance amplitude
  → O(N) integer operations, zero disk, zero float

SYSTEM_SIGNATURE():
  → Returns (n_w_total, writhe_total, jones_span_total)
  → These 3 integers ARE the complete memory state
  → A system that knows these 3 integers + the four params can
     reconstruct the braid structure of the entire memory
```
